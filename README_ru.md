# Timing Attack

---

## Что такое Timing Attack

**Timing Attack** - это способ взлома, при котором злоумышленник измеряет **время**, которое сервер тратит на обработку запроса, и по этим данным делает выводы о секретной информации. В отличие от обычного перебора паролей, здесь не нужно проверять миллионы комбинаций. Достаточно измерить, как меняется время ответа в зависимости от введенных данных. Эта атака относится к классу **side-channel** атак, потому что используется не код, а его **физические проявления** (время, питание, излучение).

---

## Как работает атака

Когда сервер проверяет пароль, он обычно сравнивает его посимвольно:

Сравнивает первый символ -> совпало

Сравнивает второй символ -> совпало

Сравнивает третий символ -> НЕ совпало -> выходит

Атакующий отправляет много запросов с разными символами и замеряет время. Тот символ, который дает **наибольшую задержку**, скорее всего правильный.

---

## Что внутри проекта

В репозитории три основных файла:

- `app.py` - уязвимый сервер (с искусственной задержкой)
- `app_secure.py` - защищенный сервер (с постоянным временем сравнения)
- `attacker.py` - программа, которая подбирает пароль по времени


```bash
python app.py
```


## Как работает код

### Уязвимый сервер (`app.py`)

Сервер хранит пароль `"86t4RF"`
При запросе он сравнивает пароль посимвольно. Если символ правильный - сервер делает задержку в **10 мс**, затем переходит к следующему. Если неправильный - сразу отвечает `ok: false`.

Именно эта задержка и создает уязвимость: атакующий видит, что правильный символ вызывает **большее** время ответа, и определяет его.

---

### Атакующий (`attacker.py`)

Атакующий перебирает символы по позициям: сначала ищет первый символ, потом второй, и так до конца. Для каждого кандидата он отправляет **20 запросов**, усредняет время и выбирает тот символ, который дал **максимальную задержку**.

Пароль собирается по одному символу за раз.

---

### Защищенный сервер (`app_secure.py`)

Вместо пароля сервер хранит его **хеш** (SHA-256). При входе он вычисляет хеш от введенного пароля и сравнивает их через `hmac.compare_digest()`.Это сравнение выполняется за **практически постоянное время**, независимо от того, сколько символов совпало.

Атакующий не видит разницы во времени - атака **не работает**.

## Результаты

### Успешная атака на уязвимый сервер (`app.py`)

Время ответа для правильного символа **заметно больше**, чем для остальных:

AAAAAA: 0.002619

BAAAAA: 0.002386

...

7AAAAA: 0.002358

**8AAAAA: 0.016290 <- время резко выросло**

9AAAAA: 0.002893

-> 8

Атакующий определяет первый символ - `8`, затем продолжает подбор:

-> 8

-> 86

-> 86t

-> 86t4

-> 86t4R

-> 86t4RF

FOUND: 86t4RF

**Результат:** пароль успешно подобран.

**Почему атака работает:**  
Уязвимый сервер сравнивает пароль посимвольно и останавливается на первом несовпадении. После каждого **правильного** символа сервер делает искусственную задержку (`sleep(0.01)`). Время ответа зависит от количества правильных символов в начале пароля - атакующий измеряет эту разницу.

Искусственная задержка добавлена **исключительно для наглядности**. В реальных системах атака работает и без нее - разница во времени составляет микросекунды или наносекунды, но ее можно измерить при большом количестве запросов. Код уязвимого сервера моделирует распространенную ошибку - посимвольное сравнение с ранним завершением проверки. Именно такая логика может приводить к утечке информации через время ответа.

---

### Неуспешная атака на защищенный сервер (`app_secure.py`)

На защищенном сервере атакующий **не может** определить правильные символы. Время ответа **почти одинаковое** для всех символов:
AAAAAA: 0.002559

BAAAAA: 0.002295

...

8AAAAA: 0.002375

9AAAAA: 0.002445

-> е

Атакующий определяет первый символ - `е`, затем продолжает подбор:

-> e

-> eV

-> eVi

-> eVi7

-> eVi7q

-> eVi7qC

FOUND: eVi7qC

**Результат:** атакующий выдает **неправильный пароль** (`eVi7qC`), который не совпадает с настоящим (`86t4RF`).

**Почему атака не работает:**  
Защищенный сервер **не сравнивает пароль посимвольно**.  
Вместо этого он:

1. Вычисляет хеш (SHA-256) от введенного пароля.
2. Сравнивает хеши с помощью `hmac.compare_digest()`.

---

## Вывод

Timing Attack - это угроза, которая работает даже без специального оборудования.  
Проект показывает, что:

- Уязвимость возникает из‑за посимвольного сравнения с ранним выходом.
- Защита достигается с помощью постоянного времени сравнения (`hmac.compare_digest`).
- Искусственная задержка не является защитой - она только усиливает эффект для демонстрации.

Этот проект полезен для понимания side‑channel атак и их предотвращения.
